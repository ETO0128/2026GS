## 时间口径（与问题一一致，必须保持）

附件1/2/4 的 10 分钟时间戳按行/列给出，顺序为 `0:10, 0:20, ..., 23:50, 0:00+1`。
本模块约定 **时间戳 = 时段起点**，且 `0:00+1 ≡ 0:00`，因此

```
时段 j = [10j, 10(j+1)) 分钟，对应原始数据第 (j-1) mod 144 列/行
period_order = np.roll(sheet_order, +1)
```

结果文件模板的行/列标签（`0:10-0:20 ... 0:00+1-0:10+1`）支持这一读法。问题二到问题四的
334 天 × 144 列数据都必须沿用同一口径。

## 模型与口径

- 充电量、放电量为**交流母线侧**电量，效率只出现在状态方程：
  `e[t+1] = e[t] + 0.9*c[t] - d[t]/0.9`
- 储能：`1200 <= e <= 10800` kWh，`0 <= c, d <= 5000/6 = 833.3333` kWh，不允许反向售电
- 结算（**变体 A：严格按计划执行**）：计划购电量照付不议；实际净负荷高于
  “计划购电量 + 计划放电 − 计划充电”的部分按 **5 倍**价紧急购电
- 执行（**变体 B：日内再调度**）：购电量不变，储能按最小化 5 倍紧急购电费重新调度，
  这是物理上更合理的口径；两种口径的差异见下
- 预测：只用当日之前的历史，按“同类型日（**周五、周六**为低负荷日，由数据判定）+
  同月”取值，可用 λ 做指数衰减。注意不能想当然按“周六周日为周末”分组
- SOC 跨日传递，仅 2025-01-01 0:00 取 6000 kWh

## 关键结果（334 天，2025-02-01 ~ 12-31）

| 策略 | 总费用/元 | 紧急电量/kWh |
| --- | ---: | ---: |
| P0 点预测·无储能 | 19,668,532 | 773,731 |
| P1 80% 分位数·无储能 | 19,168,040 | 370,387 |
| P2A 储能 LP·严格执行 | 16,643,305 | 1,085,708 |
| P2B 储能 LP·日内再调度 | 14,743,695 | 693,973 |
| P3 完美信息·储能 | 12,245,025 | 0 |
| P3' 完美预测·无储能 | 16,407,320 | 0 |
| 两阶段随机 β=0（对 P2B） | 14,457,909 | 379,276 |

- 优化空间分解：`19,668,532 − 12,245,025 = 7,423,507 = 预测误差 3,261,212（43.9%）+ 储能调度 4,162,295（56.1%）`
- 两阶段随机规划比确定性再省 285,785 元，紧急电量下降 45%；VSS = 1,638,920 元
- 临界分位：5 倍罚价 → 净需求 **80% 分位数**；本文数据上最优 τ 在 0.80~0.85，均值计划只覆盖 62.6%
- 安全余量内生：随场景波动单调增大（+10.8 → +32.3 kWh/时段），且集中在高价时段
  （最便宜档 +2.5，最贵档 +30.8 kWh/时段）

## 结果文件 result2.xlsx 的回填

`fill_result2.py` 读取官方模板 `problems/C题/附件/附件5/result2.xlsx`，写出到
`src/附件5/result2.xlsx`（与问题一 `result1.xlsx` 的做法一致），写入三个工作表：

1. **计划购电量**：334 天 × 144 个 10 分钟时段的计划购电量（kWh）
2. **充放电量**：每天 6 个四小时时段（0:00-4:00 … 20:00-24:00）的充放电量，
   以及 0:00 与 24:00 的储电量；日期只写在当天首行，0:00 储电量写在当天第 1 行、
   24:00 储电量写在当天第 2 行
3. **紧急购电量**：日期写在当天首行，同一段连续的紧急购电时段**合并为一行**
   （题目表 4 的写法）

输出保留 4 位小数；两种执行口径都支持：

| 口径 | `--variant` | 全年计划购电费 | 全年紧急购电费 | 全年合计 |
| --- | --- | ---: | ---: | ---: |
| 严格按计划执行（默认） | `A` | 12,321,192 | 4,322,113 | 16,643,305 元 |
| 购电量照付不议 + 储能日内再调度 | `B` | 12,321,192 | 2,422,502 | 14,743,695 元 |

两者都与 `run_question2.py` 的 P2A / P2B 全年结果逐一对应，可用于交叉校验。

### 官方模板的一处标签不一致（注意）

`result1.xlsx` 的最后一行为 `0:00+1-0:10+1`，而 `result2.xlsx` / `result3.xlsx` 的最后一列
写的是 `0:00-0:10+1`（起始时刻漏了 `+1`）。两者按“时间戳=时段起点、0:00+1 ≡ 0:00”
解析都对应时段 0，`fill_result2.py` 已按标签文本自动解析并对 144 个列标签做了一一对应校验，
因此不受影响；但论文里说明时间口径时最好提一句模板标签的这种写法。

## 注意事项（开工前需确认的口径）

1. **变体 A / B 的选择**：两者全年相差 1,899,610 元（11.4%）。题面对 `result2.xlsx`
   只写“充放电量”，对 `result3.xlsx` 才写“**最终的**充放电量”，提示问题二按计划执行、
   问题三才允许日内修正。该口径需写入 `模型口径` 并影响结果文件填写。
2. **日周期假设**：当前每日 `e[144] = e[0]`。若放开（终端自由），每日计划会把储电量
   压到下限、全年在低位运行，费用反而更高 8,804 元，因此需要跨日终端价值函数。
3. **场景来源**：目前只用“同月同类型”残差，低估了跨类型/跨月的水平误差，安全余量偏小。
4. **未做**：相似日聚类的参数用调度遗憾（而非 MAE）选择、调整购电量（问题三）的
   50% 违约电价口径、`result3.xlsx` / `result4-2.xlsx` / `result4-3.xlsx` 的回填、
   跨日终端价值函数（用于放宽日周期口径）。
